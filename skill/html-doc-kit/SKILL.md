# HTML 문서 만들기

뷰어와 편집기 코드는 키트가 넣습니다. **직접 쓰지 마세요.** 당신은 본문만 씁니다.

아래 `doc-kit`은 이 스킬 폴더의 `scripts/doc-kit.mjs`입니다: `node <스킬 폴더>/scripts/doc-kit.mjs`

## 새 문서

1. 본문 파일을 씁니다. **`.md`로 쓰세요.** HTML로 써야 하면 `.doc-kit/본문.html`처럼 `.doc-kit/` 안에 둡니다(작업 폴더에 둔 본문 HTML은 build 뒤 `.doc-kit/sources/`로 옮겨집니다). 표기법은 [references/input.md](references/input.md)에 있습니다.
2. `doc-kit build 본문.md -o 결과.html` (장표면 `--type slide`, A4 고정이면 `--type a4`. 모르면 빼세요. `---`만 넣어서는 장표가 되지 않습니다)
3. `doc-kit check 결과.html` 이 "완성"이어야 끝입니다.

## 이미 있는 HTML

`doc-kit ensure 파일.html` 어떤 HTML이든 완성 파일로 만듭니다. 이미 완성이면 그대로 둡니다.

## 키트로 만든 파일 고치기

완성 파일은 글꼴 때문에 2MB가 넘습니다. **통째로 읽거나 직접 고치지 마세요.**

1. `doc-kit extract 파일.html` (`-o`를 쓰지 마세요. `.doc-kit/` 폴더에 저장하고 경로를 알려 줍니다)
2. 알려 준 본문 파일을 고칩니다. `dk-asset:번호`는 그림 자리이니 그대로 둡니다. 문서 제목은 맨 위 `<title>`을 고칩니다.
3. `doc-kit apply <본문 파일> 파일.html` (사용자가 브라우저에서 고친 내용과 메모는 본문 파일에 들어 있습니다)

쪽을 일부러 지웠을 때만 `--shrink`를 붙입니다. 붙이지 않으면 쪽이 줄었다는 경고와 함께 종료 코드 1이 납니다.

## 긴 문서

본문 파일에 나눠서 이어 쓴 뒤 마지막에 한 번만 build 합니다.

## 지켜야 할 것

- 차트는 스크립트로 그리지 말고 SVG나 표로 넣습니다. 본문의 스크립트는 빠집니다.
- 그림은 로컬 파일 경로로 넣습니다. 파일 안에 들어갑니다.
- `check`가 "미완성"이면 `doc-kit ensure 파일.html`을 실행합니다. 다른 방법으로 고치지 마세요.
- `check`에 "브라우저 시험 미실행"이 나오면(샌드박스 등) 화면 판정을 못 한 것입니다. 사용자에게 그대로 알리고, 브라우저로 열어 내용이 보이는지 확인해 달라고 합니다.
- 경고(넘침, 빈 쪽, 못 찾은 그림)는 내용 문제입니다. 고칠 수 있으면 고치고 사용자에게 알립니다.
- 이미 있는 결과 파일에 다시 build하면 브라우저에서 고친 내용이 새 파일에 없습니다(백업은 남습니다). 키트 파일은 extract와 apply로 고칩니다.
- `ensure`가 "알림"으로 새 이름의 파일을 알려 주면 그 내용을 사용자에게 전합니다.
- 웹앱·웹사이트의 HTML에는 쓰지 않습니다.
- PDF·HWPX·DOCX·PPTX를 고칠 수 있는 HTML로 바꾸는 기능은 아직 없습니다. 요청받으면 없다고 알리고, 내용을 보고 다시 쓰지 마세요.

## 사용자에게 알릴 것

파일 경로와 함께: 브라우저로 열어 글자를 누르면 고칠 수 있고, 그림은 끌어서 옮기며, ⌘S 또는 Ctrl+S로 저장합니다. 인쇄·PDF 단추로 종이나 PDF로 냅니다.
